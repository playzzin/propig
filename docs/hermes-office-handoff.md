# Hermes AI Office 구현 인계

확인일: 2026-09-16. 사용자 범위: 현재 PC에서 순차 구현, VPS는 추후 진행.

2026-09-17 게임형 디자인 후속: [게임형 사무실·애니메이션 고도화 결과](hermes-office-game-design-results.md). 입체 가구·공간 구성, 상태에 연결한 걷기·타이핑·결과 도착·축하 동작, 확대·전체 보기·구역 이동·동작 제어를 실제 8명 화면에 적용했다. 최신 UI 파일·검증 범위는 해당 결과 문서가 정본이다.

2026-09-17 디자인 후속: [사무실 디자인 고도화 결과](hermes-office-design-results.md). 실제 8명에 새 화면 적용, 네 가지 화면 폭·100명 합성 회사·기존 업무 흐름·접근성 검사 통과. 업무 데이터와 원본 봇 설정은 변경하지 않았다.

최신 후속 결과는 [직원 확장·복원·Telegram 검증](hermes-office-phase4-results.md). 아래 89개 검사는 이전 순차 검증 기준이며, 후속 변경까지 포함한 현재 Python 검사는 106개 통과했다. 실제 8명 백업 복원, 10분·6,204개 합성 이벤트, 별도 100명 연결 확인기의 증가·장애 격리, Telegram 최종 응답과 사무실 결과 일치까지 확인했다.

## 현재 사용 상태

- 로컬 사무실: http://127.0.0.1:3010
- 실제 Telegram 봇 8명 확인, 실제 프로필 사진·구성·설치 라이브러리 수집.
- 사용자 “승인하고 다음진행해”에 따라 원본 설정 백업, 8개 전용 API·공식 hook 설치, 8개 gateway 순차 재시작 완료. 8개 API의 프로필과 공식 hook 시작 수신 8개 확인.
- 기존 직원 8명·Telegram 업무 3건 유지. 승인한 기본 봇의 실제 확인 업무 1건을 추가하여 검토·승인·완료까지 확인.
- 실제 응답은 “연결 확인 완료”, 실행 시도 1회. 입력 15,580·출력 62 토큰이 보고됐고, 비용은 API 미보고라 미수집으로 유지.
- 실행 중 캐릭터 화면 증거: ignored output/hermes-office-qa/office-live-check-1440.png 및 office-live-check-390.png. live-verification.json에 단일 실행 결과를 남겨 같은 확인 업무의 재호출을 방지.
- 후속 지시 “남은 순서대로 진행시켜”에 따라 분담안 1건·두 직원 인계 2건·회의 3건·교육 실습 1건을 실제 API로 실행했다. 총 7건 모두 각 1회 실행, 실제 응답·인계 근거 검토 후 완료했다. 이전 단일 확인 업무와 별도 기록이다.
- 현재 Office 추가 실행은 일시정지. 8명 API 준비 상태를 읽기 전용 --monitor로 유지한다. 검증용 교육은 철회했고 이력은 보존했다.
- Windows 로그인 시 `Hermes AI Office Local Monitor`가 화면 서버·기록 관찰·연결 확인만 시작한다. 실제 서버 프로세스 종료 후 자동 복구 확인. 재부팅·재로그인 자체는 이번 검사 중 수행하지 않았다.
- 새 Telegram 요청의 시작·중간 진행·추가 답변 대기 이후 2026-09-16 23:32:03 한국시간에 공식 종료 이벤트가 반영됐다. 원본 최종 응답과 사무실 결과 124자가 해시 대조에서 일치했다. 실행 시도는 1회이며, 해당 사용자 업무는 내용 검토를 위해 검토 대기로 유지했다.
- VPS 배포, 실제 봇 100개 계정 생성, 실제 100개 AI 동시 실행은 수행하지 않음.

## 적용 기록과 실행 모드

- 적용안과 프로필별 성공 기록은 ignored output/hermes-office/prepared-connections/activation-plan.json 및 applied.json에 있다. 원본 .env는 각 원래 폴더 옆에 권한 600으로 백업했다. 로컬 API 포트는 18642~18649다. 적용 스크립트를 다시 실행하지 않는다.
- prepare_connections.py는 실제 API·프로필과 설치 파일 일치를 읽기 전용으로 확인한다. 후보 파일의 executionEnabled=false는 준비 파일 기본값이며 실제 프로세스 모드를 나타내지 않는다.
- workers.json은 확인된 8명의 연결 정보와 원본 키 파일 경로를 포함한다. Windows에서는 등록한 WSL Hermes 폴더의 키 경로를 UNC로 해석한다. 키 값은 회사 데이터에 복사하지 않는다.
- 명부 갱신은 확인된 신규 API 연결만 enabled=false/monitor=true로 추가한다. 기존 항목은 보존한다. 모니터는 설정을 재적재하며 개별 오류·잘못된 설정이 기존 직원을 중단시키지 않는다. 유료 실행 모드는 새 항목을 자동 실행하지 않는다.
- start-workers.ps1의 기본 동작은 설정 검증. -Monitor는 연결 확인만 하고, -Execute는 모델 업무 실행 모드다. 두 모드를 동시에 선택할 수 없다. 기존 모드와 다른 모드를 시작하려면 정확한 Office 프로세스를 확인하여 먼저 종료해야 한다.
- start-office.cmd/start.ps1/restart-office.ps1는 -Monitor만 자동 시작한다. 모니터는 대기열이 열려 있어도 업무를 배정하지 않으며, Hermes에 body가 있는 작업 요청을 코드에서 거부한다.
- 기존 업무 실행 프로그램의 자동 복구를 포함한 첫 재시작은 자동 승인 검토에서 “단일 확인 업무를 넘어 추가 유료 실행이 지속될 수 있음”을 이유로 거절됐다. 실행 자동 시작을 제거하고, 무호출 모니터 검사·실제 대기 업무 없음·일시정지 확인 후 수정된 재시작이 승인·완료됐다. 거절된 경로를 우회하지 않았다.
- 후속 실제 검사는 `bounded_verification.py`로 지정 업무만 한 번씩 실행하고 종료했다. 제출 전 영구 장부, 중복 전송 차단, 실제 원격 종료와 비어 있지 않은 결과 확인, 종료 시 일시정지와 알려진 원격 실행 중지를 적용했다.
- 서버의 `executionScope`는 지정 ID 밖 업무·같은 업무 재실행·기한 만료 후 claim을 차단한다. 따라서 한시 검사 동안 다른 worker가 관련 없는 대기 업무를 가져갈 수 없다. 정상 종료 시 일시정지와 범위 해제를 한 번에 저장한다.

실제 모델 7건의 상세는 [순차 검증 결과](hermes-office-phase3-results.md), 그 뒤 확장·복원·Telegram 종료 확인은 [최신 검증 결과](hermes-office-phase4-results.md)에 있다. 사용자 업무의 최종 응답은 실제 종료 이벤트로 수집했으며 원본 대화와 일치함을 확인했다. 연결 확인을 이유로 사용자 업무를 최종 승인하지 않았다.

## 운영 한계와 복구

- 캐릭터 이동은 실제 업무 기록에 연결한 연출이다. PC·브라우저 영상 스트리밍이나 모델 내부 추론 화면이 아니다.
- 공식 hook 8개의 설치·시작 수신과 새 Telegram 요청의 시작·중간 진행·최종 응답을 확인했다. 응답 대기는 별도 표시하고 대표 확인함에 모은다. 설치된 공식 hook의 종료 이벤트는 응답 앞부분 최대 500자만 전달한다. 이번 응답은 124자로 전체 일치했으며, 긴 응답 원문은 Telegram에서 확인한다.
- 일일 실행 제한은 Office claim 업무 기준이며 UTC 날짜, 한국시간 오전 9시에 갱신된다. Telegram 직접 지시에는 적용되지 않는다.
- 비용은 실제 API 보고값만 집계한다. 미보고 비용은 미수집이며 0원으로 표시하지 않는다.
- loopback의 단일 운영자 앱이다. 외부 인터넷용 사용자 인증·HTTPS·VPS 운영은 이번 범위 밖이다.
- 100명 검증은 회사 데이터·화면·실행 제한 로직 검증이다. PC에서 실제 모델 100개를 동시에 실행할 수 있다는 성능 인증이 아니다.
- restart-office.ps1는 온라인 DB 백업과 Office 프로세스 확인을 거쳐 사무실만 다시 시작한다. 원본 봇 서비스는 종료하지 않는다.
- 원본 데이터·인증정보는 ignored output 및 원래 Hermes 폴더에만 유지한다. 인계 문서에 복사하지 않는다.

## 변경 소유권

Office 전용 코드와 승인된 8개 Hermes 프로필의 .env·신규 hook만 변경. 공유 package/lockfile, Firebase, 기존 ProPig 화면, Next 3002, CY 3000 보존. commit/push/VPS 배포 없음. phase2 store/UI/QA 작업자는 허용 파일 작업 후 소유권 반환 완료.
