작성일: 2026-09-24
대상: `/admin/storyboard`
상태: 1·2차 개선, 미제작 장면 일괄 설정, 개인 기획 프리셋, 장면 비교 검수 구현·검증 완료. 개발 서버 3002도 복구했다. 결과와 검증 한계는 [구현 인계](storyboard-ux-implementation-handoff.md) 및 [후속 결과](storyboard-remaining-work-handoff.md)에 기록했다. 아래 조사 기록은 수정 전 기준이다.

## 1. 목표

사용자가 프로젝트를 열면 현재 상태, 막힌 이유, 다음 행동을 즉시 이해하고 마지막 작업부터 이어가게 한다. 이미 있는 검색, 자동 저장, 버전 기록, 실패 복구, 예산 확인 기능을 유지하면서 연결과 표현을 개선한다.

주요 사용자: 여러 영상 프로젝트를 반복 제작하는 1인 제작자·관리자.
핵심 과업: 기획 → 이미지 확인 → 움직임 설정 → 영상 제작·검수 → 완성본 다운로드.

## 3. 목표 화면 흐름

### 프로젝트 목록

- 상단: 프로젝트 검색, 상태 필터, 새 프로젝트.
- 행: 제목, 대표 이미지, 현재 단계, 이미지/영상 승인 수, 최근 수정, 다음 행동.
- ‘확인 필요’는 사유를 붙인다. 예: ‘1개 장면 재제작 필요’, ‘완성본 갱신 필요’.
- 진행 중 필터에서도 전체 지표임을 표시하거나, 선택 필터의 지표와 전체 지표를 명확히 구분한다.
- 목록에서 편집기로 갔다 돌아올 때 작업 문맥을 유지한다.

### 편집 작업공간

```text
프로젝트 목록으로   프로젝트 제목                  저장됨
기획 → 이미지 → 움직임 → 영상·검수 → 완성본

현재 상태: 움직임 설정이 필요한 장면 2개
다음 행동: [첫 미완료 장면 설정하기]

장면 목록             선택한 장면 미리보기·설정
완료/실패/미완료        대사 / 움직임 / 필요한 수정

예상 추가 비용 · 생성 대상 장면 수 · [제작 내용 확인]
```

- 기존 5단계 모델을 유지하되 표현을 짧게 만든다.
- 기본 화면에는 현재 단계에 필요한 입력만 둔다. 모델·프롬프트·기술 정보는 기존 상세 설정에 모은다.
- 복제·가져오기·보관·삭제는 ‘프로젝트 관리’ 메뉴로 정리하고, 삭제는 제작 버튼과 분리한다.
- 모바일은 선택 장면 중심의 한 열 구조, 장면 전환과 다음 행동은 손이 닿는 위치에 배치한다. 고정 영역은 키보드·안전 여백·포커스를 가리지 않게 한다.

### 생성 직전 확인

기존 공급자 전송·유료 요청 확인 절차는 유지한다. 확인 영역에는 다음 네 가지를 먼저 보여준다.

1. 새로 생성할 장면과 재사용할 장면.
2. 이번 예상 추가 비용과 예산 상한. 가격을 알 수 없으면 추정값을 확정액처럼 표시하지 않는다.
3. 재시도에 새 요청 비용이 생기는지 여부.
4. 실행 버튼: ‘선택한 2개 장면 제작’처럼 실행 범위를 명시.

‘현재 채택 영상 비용’은 전체 사용 금액과 구별한다. 현재 값에 재시도·폐기 결과가 포함되지 않는다면 누적 청구액으로 이름을 바꾸지 않는다.

## 4. 오류·예외·상태 설계

| 상황 | 사용자에게 보여줄 내용 | 시스템 동작·검증 |
|---|---|---|
| 서버 상태 확인 중 | ‘제작 서버 확인 중’, 오래 걸리면 ‘다시 확인’ | 제한 시간과 재시도 상태를 구분. 기존 자동 복구와 충돌하지 않게 한다. |
| 응답 유실·네트워크 끊김 | ‘작업 접수 여부를 확인하고 있습니다’ | 기존 작업 ID부터 재조회. 확인되지 않았다는 이유만으로 새 유료 요청을 만들지 않는다. |
| 생성 실패 | 실패한 장면, 짧은 원인, 새 요청 필요 여부 | 재조회·입력 수정·재제작을 분리. 완료된 장면은 유지한다. |
| 일시정지 | ‘현재 장면 종료 후 멈춤’ 또는 ‘중지됨’ | 요청 중과 실제 정지를 구별. 재개 시 승인 결과 재사용을 검증한다. |
| 저장 실패 | ‘저장되지 않음’, 다시 저장 | 성공 전 ‘저장됨’ 표시 금지. 초안 보존과 이탈 방어를 검증한다. |
| 다른 탭에서 수정 | ‘다른 곳에서 변경됨’ | 기존 충돌 감지를 유지. 내 초안 보존·최신 내용 확인 경로를 설계한다. |
| 장면 삭제·순서 변경 | 변경 영향과 선택 장면 이동 | 존재하지 않는 선택 ID, 최종 영상의 최신 여부, 연결 조건을 재평가한다. |
| 완성 후 기획 변경 | ‘완성본 업데이트 필요’ 및 변경 사유 | 이전 완성본 보기와 최신본 제작을 구분. 재조립과 재생성을 구별한다. |
| 로그인 만료·권한 변경 | 재로그인 또는 접근 안내 | 타 계정 초안·구독이 섞이지 않도록 기존 계정 경계 검증을 유지한다. |
| 값 누락·잘못된 숫자 | 해당 필드의 수정 안내 | 장면 0개, 비어 있는 문구, 유효하지 않은 길이·예산, 가격 미확정, 만료된 자산 URL을 검사한다. |

개발 시에는 버튼 문구와 실제 행동을 하나의 상태 판정 결과에서 함께 만든다. 현재 `primaryIntent`와 `primaryLabel`은 서로 다른 우선순위 분기로 계산되어, 실패/일시정지와 미완료 기획이 겹칠 때 문구·행동 불일치가 생길 가능성이 있다. 이는 코드상 위험이며 이번 브라우저 조사에서 확정 재현한 결함은 아니다. 상태 조합 테스트로 확인한다.

## 5. 실행 순서와 범위

### 2차: 복구·모바일·가독성

- UX-04~UX-07.
- 오류 원인과 해결 버튼을 같은 영역에 표시, 중복 안내 축소, 모바일 핵심 수치 유지.

### 3차: 반복 제작 속도

- 사용 빈도 확인 후 선택 장면 일괄 설정, 개인 기획 프리셋, 장면 비교 검수 등을 도입한다.

- 생성 모델 추가나 전체 화면 재작성은 선행 조건이 아니다.

## 7. 이번 조사에서 수행한 검증과 한계

- 실제 로그인 상태의 프로젝트 목록, 문제 해결 진입, 영상 제작 화면을 확인했다.
- 검색 → 프로젝트 열기 → 대시보드 복귀에서 검색어 유실을 재현했다.
- 영상 장면 설계 상태의 프로젝트에서 ‘이어서 제작’이 `storyboardMode=storyboard`로 이동하는 것을 확인했다.
- 1440×1000 데스크톱과 390×844 모바일 화면을 확인했다. 모든 모달·키보드 조작·전체 화면 조합을 검사한 것은 아니다.
- `verify:storyboard-race-safety`: 통과. 코드상의 안전장치 존재 검사이며 실제 네트워크 경합 전체의 보장은 아니다.
- `verify:storyboard-production-state`: 통과.
- `verify:storyboard-workflow-v2`: 통과.
- `verify:storyboard-accessibility-performance`: 공통 메뉴 조건식 문자열 검사에서 실패. 실제 조건은 메뉴가 열렸을 때만 배경을 렌더링하므로 이 실패만으로 실제 메뉴 차단 결함을 주장하지 않는다. 중단 지점 뒤의 검사는 이번 실행에서 검증되지 않았다.
- 프로젝트 doctor는 Windows Python 실행 연결 문제로 실행하지 못했다. 역할·운영 문서는 직접 읽었다.
- 기획 문서만 작성했다. 제품 코드를 변경하지 않아 전체 type/lint/build는 실행하지 않았다.
- 유료 생성, 재제작, 저장 충돌 유발, 프로젝트 삭제, 운영 데이터 변경, 배포는 수행하지 않았다. 실제 공급자 장애·과금·백그라운드 복구의 종단 검증은 후속 구현 시 별도 범위로 진행한다.
