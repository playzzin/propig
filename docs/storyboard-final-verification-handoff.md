### 200% 확대 검증 상태

- 사용자에게 200% 설정 완료 응답을 받았다. 그러나 연결된 Chrome 검증 탭은 `Page.getLayoutMetrics`에서 `cssVisualViewport.zoom: 1`, 유효 폭 2560을 계속 보고했고 IAB도 zoom 1이었다. 따라서 200% 검증을 통과로 기록하지 않는다.
- Chrome 설정 화면 접근은 브라우저 도구의 URL 보안 정책으로 차단됐다. 다른 제어 경로나 CDP 변경으로 우회하지 않았다. 설정한 탭의 일치 여부를 사용자에게 확인 요청한 상태다.
- 실제 배율 2가 확인되면 대시보드 → 편집 → 비교·생성 확인 영역의 가로 넘침, 버튼 접근, 키보드 포커스를 검사한다. 기존 390/720/1440px 반응형 검증을 실제 200% 검증으로 대체하지 않는다.

### 좁은 화면에서 가려지는 제작 버튼 수정

- 320px 로그인 화면에서 ‘장면 추가’의 실제 위치가 x=351~387px로 화면 밖에 나가는 것을 확인했다. body에 가로 넘침이 없어도 내부 overflow 때문에 버튼이 가려질 수 있었다.
- 장면 구역 제목과 버튼을 줄바꿈하도록 바꾸고, 모바일에서는 장면 수를 독립된 줄에 표시한다. 제목용 span 스타일의 적용 범위를 좁혀 장면 수까지 덮어쓰지 않게 했다. 생성·장면 추가 버튼은 줄어들지 않는 최소 44px 높이를 사용한다.
- 실제 320/390/720/1440px에서 두 버튼의 경계가 화면 안에 있고 높이가 44px임을 확인했다. 320px에서 키보드로 일괄 생성 확인을 열고 취소했다. 동의하지 않은 실행은 비활성, 확인 영역과 두 버튼도 화면 안에 있었다.
- 320px 프리셋 펼침, 한 장면 비교의 빈 결과·장면 부족 안내, 선택 필드·비교 카드 배치를 확인했다. 의도적인 빠른 시작 템플릿 가로 스크롤은 유지했다. 임시 viewport 변경은 검사 후 reset했다.
- 위 검사는 유효 폭에 따른 반응형 검사이며 실제 브라우저 200% 배율 검사를 대신한다고 주장하지 않는다.

### 불완전한 병합 결과로부터 이전 완성본 보호

- 실제 VideoProductionPanel을 React StrictMode로 실행하고 IO만 격리한 검사에서, 완료 응답의 clip ID/영상 URL 중 하나가 없을 때 이전 완성본과 새 결과가 섞이는 문제를 재현했다.
- 정상 완료이면서 두 값이 모두 있는 결과만 완성본 ID·URL·artifact ID를 함께 교체한다. 실행 중·업로드 중·실패·취소·불완전한 완료 결과는 이전 완성본을 보존한다.
- 개별 장면 재생성에서도 같은 불일치를 clip-only/URL-only 두 경우로 재현했다. 두 값이 모두 갖춰지지 않은 완료는 실패 안내를 제공하고 기존 ID·URL·artifact·마지막 프레임을 유지한다. 정상 새 영상에 마지막 프레임이 없으면 이전 영상의 프레임을 재사용하지 않고 null로 둔다.
- 기존 9개 + 병합 19개 + 장면 재생성 4개, 총 32개 fixture PASS를 lead가 최종 코드로 독립 재실행했다. 미승인/파일 누락 장면의 병합 차단, 장면 순서·편집값 전달, 재시도 뒤 늦은 이전 완료 응답 차단, 기존 결과 보존, 정상 완료 manifest·최신성 갱신, 중복 정리 방지, 부분 장면 결과의 실패 안내와 원본 보존, 정상 장면의 새 검수 필요 상태를 포함한다.
- 실제 외부 요청·원본 삭제는 0회다. service 제출과 파일 정리는 가짜 함수이며 공급자 품질·실제 FFmpeg 실행의 증거가 아니다.
