# 그뚠 대시보드 첫 버전

| 환경 | 사용자가 여는 곳 | 화면에 위젯을 놓는 방법 |
| --- | --- | --- |
| 그뚠웹 | 브라우저에서 `/propig` | 상점에서 앱을 등록하고 대시보드에서 순서와 표시 여부를 조정한다. 설치한 웹도 대시보드에서 시작한다. |
| 그뚠앱 · Android | 대시보드 APK의 앱 아이콘 | 대시보드의 ‘홈 화면에 오늘 요약 추가’ 또는 런처의 ‘위젯 → 그뚠앱’. ‘오늘 습관’ 위젯은 선택한 체크형 습관을 홈 화면에서 바로 기록한다. |
| 그뚠앱 · iPhone | iOS 앱의 대시보드 | 홈 화면을 길게 눌러 위젯 추가 메뉴에서 그뚠앱의 ‘오늘 요약’을 고른다. 작은 크기와 중간 크기를 지원한다. 앱에서는 기존 이메일 계정으로 로그인한다. |
| 그뚠뎃 · Windows | 기존 C# WPF 앱 | 앱의 ‘위젯’ 메뉴에서 오늘 습관, 메모, 할 일, 시스템 정보, 시계·날씨, 국내 증시 등을 각각 띄운다. 창별 위치·크기·항상 위 설정을 PC에 보관한다. |

## 적용 순서와 데이터

1. 기존 웹 대시보드를 공용 화면으로 사용한다. 웹·Android·iPhone·Windows의 대시보드 배치는 기기 내에 보관한다. 첫 실행은 기존 배치를 읽고 이후에는 해당 환경의 배치를 저장한다. 계정의 메모, 할 일, 습관, 상점 등록은 기존 Firebase 저장 경로를 사용한다.
2. 휴대폰 대시보드에서 로그인과 두 데이터 구독이 준비되면 오늘 할 일·습관의 완료 수와 전체 수를 OS 위젯에 전달한다. 날짜 선택기를 바꿔도 홈 화면은 기기 기준 오늘을 보여 준다. 예정일이 없는 미완료 할 일도 전체 수에 포함한다. 휴대폰 앱에서 대시보드를 열면 기록을 다시 읽는다. 앱이 닫혀 있는 동안은 마지막 갱신 시각을 표시하며, 날짜가 지나면 대시보드를 열도록 안내한다.
3. Android는 AppWidget과 앱 전용 저장소, iPhone은 WidgetKit과 App Group `group.com.propig.app.widgets`를 사용한다. 로그아웃·계정 교체 시 이전 집계를 지운다. 위젯용 요약은 개수와 날짜·시각만 담는다. 앱 비밀번호, 인증 토큰, 종목 API 키, 메모 본문은 요약에 포함하지 않는다. 위젯을 누르면 같은 앱의 대시보드로 돌아간다.
4. Windows는 기존 패키지 ID, 사용자 설정, 로컬 C# 수집기와 MiraBox 실행 확인을 사용한다. PC 상태 공유를 켜면 같은 계정으로 웹과 휴대폰에서도 마지막 전송 시각을 확인할 수 있다. MiraBox 동작 승인은 연결된 Windows PC에서 받는다.

## 빌드와 설치

- Android 배포 진입점은 `android/app`이다. 기존 `com.propig.app`의 서명과 버전 체계를 이어받고 `android/habit-store`의 체크형 위젯 소스를 함께 컴파일한다. `/downloads/android/shop.apk`는 웹 바로가기용 기존 패키지다. 테스트 기기에는 Actions의 `propig-android-packages` 안에 있는 `app-debug.apk`를 설치한다. 다른 서명의 기존 앱이 설치된 기기는 같은 서명으로 빌드한 업데이트가 필요하다.
- iOS는 `npx cap sync ios` 후 `ios/App/App.xcodeproj`의 App 스킴에서 앱과 TodayWidget 확장을 함께 빌드한다. 타깃 구성의 원본은 `ios/App/project.yml`이며 변경 후 macOS에서 `xcodegen generate`를 실행한다. 시뮬레이터용 앱은 Actions의 `geuttun-ios-simulator`에서 받는다. 실제 iPhone 및 TestFlight는 Apple 개발팀으로 앱과 확장을 서명하고 두 App ID에 같은 App Group을 연결해야 한다. iPhone용 Google 로그인을 추가할 때는 Firebase의 iOS 앱 등록과 Google 클라이언트 설정이 필요하다.
- Windows 패키지는 `propig-windows-msix`에서 받는다. 현재 Store 제품에 배포하려면 기존 제품 ID와 게시자 서명으로 패키지를 제출하고 ‘그뚠뎃’ 표시 이름을 Store 목록에도 반영한다.
- `Habit store packages` 수동 실행의 `mobile_web_origin`에 해당 브랜치의 Firebase 미리보기 출처를 넣으면 그 웹을 여는 모바일 테스트 빌드가 생성된다. 기본 빌드는 운영 Hosting을 연다. 정식 배포 순서는 웹 게시, 서명한 모바일·Windows 빌드의 실제 기기 확인, 각 스토어 제출 순이다.

## 검수 기준

- 웹 미리보기를 휴대폰·PC 너비로 열어 그뚠웹 제목, 대시보드의 위젯 배치, 환경별 설치 안내와 전용 웹 매니페스트를 확인한다.
- Android 에뮬레이터에서 AppWidgetHost로 두 위젯을 추가하고 오늘 요약을 눌러 대시보드를 연다. iPhone 시뮬레이터에서 앱·확장을 함께 설치하고 App Group 및 위젯 링크로 재실행되는지 확인한다.
- 실제 기기 인수 검수에서는 같은 계정으로 로그인하고 대시보드에 있는 오늘 완료 수와 위젯 값을 대조한다. 날짜 변경·로그아웃·계정 전환을 확인한다. Windows에서는 C# 위젯을 별도 창으로 열고 위치·크기 복원과 사용자 계정 연결을 확인한다.
