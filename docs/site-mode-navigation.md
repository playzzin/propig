# 사이트 모드별 메뉴 운영

후속 저장 무결성 개선과 최신 검증 방법은 [메뉴 저장·전환 후속 검증](menu-save-reliability.md)을 참고한다. 아래 최초 측정 수치는 당시 기록이며 최신 반복 측정과 구분한다.

## 관리 위치와 역할

- `/admin/menu`: 편집할 사이트 탭을 선택한 뒤 메뉴 순서, 폴더, 경로, 접근 권한을 관리한다.
- 상단 사이트 전환: 실제 사이트 홈으로 이동한다. 관리자 편집 대상 탭과는 다른 상태다.
- 계정 메뉴: 사이트 업무 메뉴와 별도로 관리한다.
- 공개 기업 콘텐츠에서도 모드 전환 및 페이지 끝까지 스크롤할 수 있어야 한다.

## 전환 계약

1. 사용자가 모드를 선택한 뒤 같은 이전 URL의 effect가 선택을 되돌리지 않는다.
2. 새 URL이 실제로 확정됐을 때 route 모드를 동기화한다.
3. 접근 가능한 모드만 표시하며, 메뉴 노출은 공통 권한 필터를 통과한다.
4. 모드 전환은 메뉴 데이터를 매번 기본값으로 초기화하지 않는다.
5. 실시간 메뉴가 도착했다면 오래된 초기 원격 조회로 덮어쓰지 않는다.
6. 초기 조회 timeout 후 로컬 fallback이 표시됐더라도 정상 원격 복구는 허용한다. 그 사이 새 실시간 snapshot이 도착한 경우에만 늦은 결과를 차단한다.
7. 브라우저 저장소는 캐시다. 저장소 차단/용량 초과가 live 메뉴 수신을 중단시키지 않는다.

## 검증

- `npm run verify:admin-menu`: 정적 메뉴 계약과 실제 비동기 캐시 경쟁 검사.
- `node scripts/verify-menu-react-lifecycle.mjs`: React 모드 전환·메뉴 구독 생명주기 회귀.
- `npm run verify:route-shell`: 공개/업무 shell 경계.
- `npm run verify:navigation-performance`: 기업 콘텐츠 경로 이동, 1366px/390px 탐색 유지.

전환 속도는 개발 첫 compile과 warm navigation을 구분한다. 브라우저 검사에서 단순 고정 시간 대기나 모드 라벨 변경을 완료로 보지 않고 목적지 URL과 콘텐츠 준비를 확인한다. 실제 배포 성능 개선율은 같은 production 조건의 전후 측정 없이 주장하지 않는다.

## 로컬 production 검증 결과

- 최종 webpack production build 성공: 정적 페이지 73/73.
- 기업 콘텐츠 4개 경로 이동: 데스크톱 65~374ms, 390px 모바일 76~178ms. 변경 전 기준값이 없어 개선율을 의미하지 않는다.
- 공개 모드 블로그 → 기업 → propig 전환: 목적지 URL·현재 모드 일치, sidebar 1개, 가로 overflow 없음, pageerror 없음.
- 모드 전환 측정에는 500ms 안정화 대기가 포함되며 모바일 기업 홈에서 4184ms가 한 번 관측되었다. 홈 콘텐츠 준비 지연은 후속 성능 과제다.
- 접힌 sidebar popover의 이전 모드 링크 제거, 모바일 drawer inert·Escape·배경 닫힘·포커스 복귀 통과.
- 구형 `/admin/menu/AdvancedMenuManager` → `/admin/menu` 이동과 비로그인 경계 통과.

## 남은 운영 주의

관리 화면의 저장 테스트는 테스트용 계정/격리 데이터로 수행한다. 실제 사용자 메뉴나 권한 설정을 QA 목적으로 저장하지 않는다. 서버 API 권한 검사는 클라이언트 메뉴 숨김과 별도로 유지한다.
