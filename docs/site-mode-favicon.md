# 사이트 모드 파비콘 계약

## 문제와 근거

운영의 기업·propig·블로그 페이지에서 기본 `/favicon.ico`와 동적 `icon`/`shortcut icon`이 동시에 존재했다. DynamicFavicon은 MenuContext의 현재 모드보다 메뉴 path 첫 일치를 우선하여, 메뉴 UI와 독립적으로 모드를 다시 추론하고 있었다. 기존 구현은 5초 이미지 로딩 검사가 실패하면 동적 아이콘을 제거했다.

운영 설정의 기업과 shop(propig)에는 같은 이미지 URL이 저장되어 있었다. 동일 이미지가 보이는 것은 이 두 모드의 경우 설정 의도도 확인해야 한다. 임의로 다른 이미지로 변경하지 않는다. 관리자용 PNG는 약 1.5MB이므로 작은 탭 아이콘으로 교체하는 것이 권장되지만 사용자의 원격 설정·원본 자산은 변경하지 않는다.

## 개선 계약

- 파비콘은 MenuContext의 현재 모드를 정본으로 사용한다. 별도 경로 추론을 중복하지 않는다.
- 기본 ICO 등 경쟁하는 탭 아이콘과 활성 모드 아이콘이 동시에 브라우저 후보로 남지 않게 한다.
- 빠른 모드 전환 뒤 오래된 이미지 실패 결과가 새 아이콘을 제거하지 않는다.
- 외부 이미지 URL의 서명·쿼리 값을 임의로 변경하지 않는다.
- 실패나 설정 부재는 전역 설정 및 기본 아이콘으로 복구한다.
- 브라우저 탭 아이콘과 PWA 설치·홈 화면 아이콘은 별도 계약이다.
- 관리자 브랜드 화면에 동일 파비콘 사용 모드를 표시하고 가벼운 정사각형 이미지 사용을 안내한다.

## 최종 로컬 검증

- 실제 React 컴포넌트의 격리 Chromium 회귀 18개 통과: 모드 정본, race, late 결과, 외부 서명 URL 보존, alias, malformed data/blob, 5초 timeout, fallback, metadata 재삽입과 unmount 복원.
- Next 프로덕션 빌드와 TypeScript, 수정 파일 ESLint 통과.
- 새 빌드에서 실제 공개 설정을 사용해 기업→블로그→propig→기업, reload/back 모두 단일 탭 icon 및 원본 이미지 decode 확인. pageerror 없음.
- 기존 Sidebar 데스크톱·모바일 회귀 통과. 운영 기본 ICO 경쟁 상태는 수정 전 검사에서 실패하고 새 빌드에서는 통과했다.
- `npm run verify:site-favicon`을 release-browser 명령에 포함했다. 관리자 로그인 저장·실제 브라우저 chrome의 탭 픽셀 및 PWA 설치 아이콘은 이번 검증 범위가 아니다.

## 검증 범위

실제 컴포넌트를 실행하는 격리 브라우저 회귀와 새 production 빌드의 실제 공개 설정 모드 전환·reload·back 검증을 구분한다. 현재 작업은 원격 설정 저장이나 운영 배포를 포함하지 않는다.
