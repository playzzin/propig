# 직원 확장·복원·Telegram 최종 응답 검증

확인일: 2026-09-16. 실제 직원 8명, 로컬 PC 범위. VPS는 추후 단계다.

## 완료한 변경

| 항목 | 변경과 확인 |
|---|---|
| 100명 탐색 | 프로필 개수 대신 고유한 실제 봇 수를 기준으로 한도 적용. 기본·미연결·중복 프로필 뒤의 100번째 봇 발견 검사 통과 |
| 신규 연결 | 명부 갱신 후 기존 API가 확인된 새 연결을 확인기에 추가. 새 항목은 enabled=false, monitor=true이며 기존 항목을 보존 |
| 자동 반영 | 확인기가 새 설정을 검증하고 새 직원만 추가. 실제 격리 프로세스에서 8→99→100명으로 증가, 재시작 없음 |
| 개별 장애 | 직원 한 명의 연결 파일 오류를 격리. 다른 99명 연결 유지, 잘못된 전체 설정에서도 기존 연결 유지 |
| 선택 설치 | 신규 프로필만 준비·설치하는 경로 추가. 기존 multiplex hook·인증 파일·기존 적용 기록 보존 검사 통과 |
| 백업 | 원본 존재·Office 장부·무결성 확인 후 읽기 전용으로 복사. 누락/손상 원본에서 빈 DB를 생성하거나 성공 보고하지 않음 |
| 복원 | 아직 없는 새 폴더에 실행이 일시정지된 사본만 생성. 덮어쓰기 차단, 연결 설정·키 복사 없음 |

새 연결의 monitor=true는 연결 확인만 허용한다. 실제 AI 업무를 자동 실행하도록 허용하는 설정이 아니다. 유료 실행 모드는 시작 당시 선택한 직원만 사용하며 신규 항목을 자동 실행하지 않는다.

## 실제 검증 결과

- **현재 8명:** 명부 갱신, API 준비 8개, 공식 hook 설치 일치 8개. 명부 갱신 경고 없음. 추가 모델 호출 없음.
- **Telegram 최종 응답:** 2026-09-16 23:32:03 한국시간에 실제 종료 이벤트 수신. 원본 대화의 최종 응답과 사무실 결과 124자의 해시가 일치하고 실행 시도는 1회다. 시작·진행·답변 대기·최종 응답·검토 대기까지 연결을 확인했다. 원래 사용자 업무의 내용상 승인은 하지 않고 검토 대기로 유지했다.
- **실제 회사 백업 복원:** 직원 8명·업무 12건을 임시 사무실에 복원. 결과·이전 결과·감사·실행·중복 방지·사용량 장부의 건수와 해시 일치. HTTP 상태·업무 보고서 일치, 원본 백업 불변.
- **10분 부하 시험:** 합성 사무실 100명, 604.86초, 이벤트 6,204건, 결과 100개. 중간 종료·재시작, 중복 억제, DB 무결성 통과. 쓰기·조회 p95 각각 32ms.
- **100명 연결 확인기:** 합성 API를 대상으로 실제 확인기 프로세스 실행. 8명→오류 직원 제외 99명→설정 수정 후 100명. 같은 프로세스 유지, provider POST 0건, 업무 생성 0건.
- **자동 검사:** Office Python 106개 통과. 실제 명부의 PC·모바일 화면과 8개 메뉴 검사 통과. 이번 후속 변경에는 화면 코드 변경이 없다.

100명 시험은 회사 기록·연결 확인기 확장 검증이다. 실제 100개 봇 계정의 유료 모델 동시 실행 검사나 하루 이상 운영 검증이 아니다.

현재 설치된 Hermes의 공식 종료 이벤트는 응답 앞부분 최대 500자를 전달한다. 이번 124자 응답은 전체가 일치했으며, 더 긴 응답의 전체 원문은 Telegram에서 확인한다.

## 새 봇이 준비됐을 때

1. 실제 Telegram 봇을 Hermes 프로필에 연결한다. 자동 갱신 또는 **봇 정보 확인**으로 직원이 입사하고 빈 좌석과 필요한 층이 추가된다.
2. 해당 프로필의 기존 로컬 API가 확인되면 읽기 전용 연결 확인기에 자동 추가된다. 기존 직원과 실행 선택은 유지한다.
3. API나 공식 hook이 없으면 신규 프로필만 대상으로 연결 준비안을 만든다. `prepare_connections.py --profiles <신규 프로필>` 및 `activate_connections.py --profiles <신규 프로필>`은 기존 8개 연결을 전체 재설치하지 않는다. 기본 동작은 준비이며, 실제 인증 추가·서비스 재시작은 검토한 적용 단계에서 수행한다.
4. 신규 직원의 실제 실행은 업무와 비용 범위를 정한 뒤 한 건부터 확인한다.

## 복원 확인

백업은 `output/hermes-office/backups/`에 있다. 검증용 사본은 원래 사무실을 교체하지 않는다. 새 사본에는 인증키·실행 연결 설정이 들어가지 않으며 실행은 일시정지된다.

담당자용 절차:

```text
maintenance.py --data output/hermes-office
restore_check.py --backup <백업 sqlite 경로> --report <새 결과 JSON 경로>
maintenance.py --restore-from <백업 sqlite 경로> --destination <아직 없는 새 폴더>
```

복원은 Windows 로컬 NTFS에서 확인했다. 배타적 게시에 하드 링크를 사용하므로 지원하지 않는 저장장치에서는 덮어쓰기 없이 실패한다.
