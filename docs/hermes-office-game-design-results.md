# 게임형 사무실·애니메이션 고도화 결과

확인일: 2026-09-17. 로컬 사무실의 실제 직원 8명 화면에 적용했다.

## 달라진 화면

- 따뜻한 사무실 경영 게임을 닮은 2.5D 공간: 두께가 있는 벽·타일 바닥·창문·입구·화분·업무 구역·공용 통로를 구성했다.
- 책상에 모니터·키보드·컵·책·의자를 배치했다. 회의실은 원탁과 의견 보드, 교육실은 칠판과 학습 책상, 휴게실은 소파와 커피 머신, 명예의 전당은 트로피와 상장으로 구분한다.
- Telegram 프로필 얼굴, 저장된 몸체 색·캐릭터·소품을 사용한다. 프로필 사진이 없거나 표시되지 않으면 읽기 쉬운 이니셜로 대신한다.
- 직원이 다른 공간으로 이동해도 원래 책상은 남긴다. 실제 직원이 없는 자리는 ‘빈 좌석’으로 표시한다.
- 직원 수와 가장 먼 좌석에 맞춰 업무석 행을 늘린다. 기존 25석 단위 4개 층, 방 위치·크기 편집, 좌석 맞교환을 유지한다.

## 동작과 실제 상태

| 상황 | 화면 동작 |
|---|---|
| 연결된 직원의 최근 실제 작업 | 손 타이핑, 모니터 화면 변화, 진행 말풍선 |
| 추가 답변 대기 | 질문 말풍선, 타이핑 정지 |
| 회의·교육 업무 확인 | 공간이 있는 해당 방으로 짧게 걸어서 이동 |
| 최근 결과 도착 | 업무석 복귀, 체크 표시의 짧은 반응 |
| 검증된 포상·교육 적용 기록 | 해당 공간의 짧은 축하·안내 연출 |
| 대기 | 가벼운 호흡 동작, 작업 중으로 표시하지 않음 |
| 연결 끊김·활동 중지 | 상태 안내, 캐릭터 움직임 정지 |
| 최근 진행 확인 부족 | ‘실행 확인 중’, 타이핑 없음 |

이동은 업무 목적지가 바뀔 때만 실행한다. 같은 상태가 갱신될 때마다 이동을 다시 시작하지 않는다. 방이 너무 작거나 자리보다 인원이 많으면 남은 직원은 업무석에서 실제 상태를 표시한다. 걷기는 짧은 시각적 경로이며 가구 장애물을 계산하는 게임 물리 엔진은 아니다.

## 화면 조작

- **− / +**: 지도 확대·축소. **퍼센트 버튼**: 기본 배율. **전체 보기**: 현재 층 전체에 맞춤.
- **업무석 / 공용 공간**: 지도 안에서 해당 구역으로 이동.
- **애니메이션 끄기 / 켜기**: 이동 중에도 즉시 정지하며 이 브라우저의 선택을 유지.
- 운영체제의 **동작 줄이기**를 우선 적용한다. 배치 편집 중과 페이지가 숨겨졌을 때도 동작을 멈추도록 구현했다.
- 모바일에서는 지도 안을 스크롤하거나 전체 보기를 사용할 수 있다. 전체 보기에서 작아진 이름은 확대해 확인한다.
- 지도와 직원은 키보드로 접근할 수 있다. 기존 직원 상세창과 초점 복귀 동작을 유지한다.

## 실제 검증

| 검사 | 확인 결과 |
|---|---|
| TypeScript, 변경 React 파일 ESLint, 사무실 독립 빌드 | 통과 |
| 실제 명부 읽기 전용 검사 | 직원 8명, PC·모바일, 8개 메뉴·상세창·Escape, 화면 넘침·실행 오류 없음 |
| 접근성 자동 검사 | 실제 8개 메뉴 통과. 연결 끊김·사진 없음·동작별 합성 화면도 통과 |
| 게임 전용 검사 | 7개 시나리오 통과: 상태 구분·이니셜 대비·저장 색상·확대/축소·회의/교육 이동·이동 중 정지·설정 유지·결과 복귀·모바일·동작 줄이기 |
| 100명 디자인 검사 | 390·768·1440·1920px, 4층에 각 25명, 직원 겹침과 페이지 가로 넘침 없음. 빈 사무실·연결 끊김·조회 실패 확인 |
| 기존 기본 회사 업무 | 100명·4층, 부서·검토·승인·완료·포상·교육·보고서·재접속 통과 |
| 기존 확장 회사 업무 | 협업 계획 편집·실행 등록, 교육 적용/철회, 방 편집, 좌석 1↔100 이동, 답변 대기/재개 통과 |
| 독립 읽기 전용 검토 | 4개 화면 폭, 합성 100명·9가지 상태, 이동 중 정지 확인. 발견한 대비·이름표 간격 문제 수정 후 재검증 통과 |
| 사용자 미리보기 | 앱 안의 기존 사무실 탭을 새로고침하고 게임형 지도·새 조작 버튼 표시 확인 |

초기 검사에서 발견한 제목 글자 대비, 이름표와 다음 행 상태의 겹침, 가구 그림의 중첩 위치, 작은 방의 직원 배치 공간, 연결 끊긴 직원의 글자 대비를 수정했다. 마지막으로 저장된 직원 색상이 기본 색에 가려지는 문제도 수정하고 회귀 검사에 포함했다.

100명 검사는 분리된 합성 회사로 진행했다. 이번 변경은 화면에 관한 작업이며 유료 모델 호출·운영 데이터 수정·원본 봇 설정 변경은 없었다. 실제 업무 영상이나 모델 내부 사고를 스트리밍하는 기능은 아니다. VPS 및 실제 100개 모델 동시 실행 검증은 이번 작업 범위에 포함하지 않는다. 자동 접근성 검사만으로 모든 보조 기기의 사용성을 보장하지는 않는다.

## 파일과 검증 자료

- `src/components/admin/hermes-office/OfficeScene.tsx`: 기존 배치 편집과 새 게임 화면 연결
- `GameOfficeWorld.tsx`: 카메라·공간 구성·층별 배치·동작 설정
- `GameOfficeActor.tsx`: 실제 프로필 캐릭터·이동과 상태 표현
- `GameOfficeArt.tsx`: 별도 통신 없는 벡터 가구와 장식
- `gameSceneState.ts`: 실제 기록에서 화면 상태 계산
- `office-game.css`: 게임형 공간·가구·캐릭터·반응형·동작
- `scripts/hermes-office/game-check.mjs`: 분리된 게임 동작 회귀 검사
- ignored `output/hermes-office-qa/game/verification.json`: 게임 검사 결과. 같은 폴더의 `office-8.png`, `office-fit-390.png`는 합성 화면.
- ignored `output/hermes-office-qa/design/verification.json`: 100명·4개 폭 검사 결과.
- ignored `output/hermes-office-qa/game-independent-100.json`, `game-independent-movement.json`, `game-independent-offline-accessibility.json`: 독립 검토 및 수정 후 확인.

사용법은 [사용 안내](hermes-office-user-guide.md#게임형-사무실-사용하기), 전체 회사 기능의 현재 상태는 [구현 인계](hermes-office-handoff.md)에서 확인한다.
