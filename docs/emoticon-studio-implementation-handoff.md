## 저장·과금 계약

- `draft.frameMeta`를 저장 기준으로 사용하고, 연결 변경은 `getFrameSlotPatch`에서 함께 처리한다. 생성 원본에는 최초 편집 정보도 함께 기록해 초안 저장 실패 후 복구를 돕는다.
- 서버에 도착했는지 불명확한 요청은 시간이 지났다는 이유만으로 재전송하지 않는다. 예약 전 거절만 `requestSubmitted:false`로 새 시도를 허용한다.
- 여러 탭의 AI 실행은 Web Locks로 직렬화한다. 다른 탭이 초안을 변경하면 현재 탭은 덮어쓰기를 멈추고 백업 또는 최신 작업 불러오기를 안내한다.
- ZIP의 AI 기록에는 요청 식별자·모델·비용·연결 정보만 포함한다. 토큰, API 키, 원문 이미지 요청은 포함하지 않는다. 서버 결과 조회는 원래 생성 계정으로 인증해야 한다.
- 실제 이미지 일일 예산의 잔여값은 UTC 기준 예약/사용 장부다. 공급자의 최종 청구서를 뜻하지 않는다. 기획 비용은 표시하지만 이미지 예산에 포함되는 것으로 표현하지 않는다.
- 복구 서버에 영구 보관을 약속하지 않는다. 대용량 결과는 기존 보존 정책을 따르므로 결과를 확인한 뒤 작업 ZIP으로 보관해야 한다.

## 플랫폼 안내 확인

2026-09-24 공식 자료와 화면 안내를 대조했다. 파일을 만들었다는 사실과 플랫폼 제출·심사 완료를 구분한다.

- [카카오 움직이는 이모티콘](https://kakaoemoticonstudio.notion.site/animated-emoticon): WebP 360×360, 파일당 650KB, 최대 24프레임·4회 반복과 아이콘 규격을 안내한다. 작업용 변환 결과는 공식 제작 도구의 최종 제출 요건 충족을 보장하지 않는다.
- [OGQ 움직이는 스티커 도움말](https://supportogq.zendesk.com/hc/ko-kr/articles/51412318704921): 740×640 GIF, 1MB·100프레임, 첫·마지막 프레임 일치를 안내한다. 최신 도움말에 명시되지 않은 3초 기준은 기존 작업 참고값으로 표시한다.
- [LINE 애니메이션 스티커](https://creator.line.me/en/guideline/animationsticker/): 정적 스티커 규격이 섞여 있던 캔버스를 최대 320×270으로 수정했다. APNG, 5~20프레임, 1~4회 반복·총 4초 이내의 별도 제작 요건을 안내한다.
- [Telegram 스티커](https://core.telegram.org/stickers): 정적 PNG/WebP와 움직이는 TGS·VP9 WebM을 구분한다. GIF는 작업 확인용으로 표시한다.
- 빈 프레임의 이미지 추가는 선택한 장면·프레임부터 채운다. 고정 크기 작업 모드에는 임의 크기 조절을 암시하지 않도록 ‘자유 캔버스’라는 이름을 사용한다.

- 추가 격리 브라우저 검사: 장면 검색·검색 결과 없음·최근 사용 저장, 미완성 필터, 확인 필요 항목의 빈 상태, 검수의 미완성/미연결 수정 바로가기, Tab·Shift+Tab·Enter 편집 접근이 통과했다. 실제 UI에서 선택한 두 프레임의 시간을 `[180,140,140] → [230,230,140]`으로 바꾸고 실행 취소 시 원래 값으로 정확히 복원했다. 유료 요청 0.
- lead 독립 메모리 검사: 실제 TSX의 일괄 적용·실행 취소·다시 실행 함수를 실행해 `[80,90,125] → [240,240,125] → [80,90,125] → [240,240,125]`와 저장 메타 일치를 확인했다. 선택하지 않은 프레임의 시간도 보존됐다.
- 모바일 이미지 선택 버튼: 기존 약 y=1,902px → y=649.5~695.5px. 하단 주 버튼 y=790~834px. 현재 단계와 저장 상태도 첫 화면에 표시.
- 전체 `npm run build`: 기존 배포 경계 검사기가 `boundaryManifest.clientOnlyCalls`를 읽는 단계에서 중단했다. 해당 접근만 메모리에서 보호해 추가 진단하면, 이 변경 밖의 `hermes-office/AuditLog.tsx`, `taskHistoryApi.ts`의 `/api/history`가 배포 경계 목록에 등록되지 않은 문제도 확인된다. 검사기·해당 파일·배포 정책은 수정하거나 우회하지 않았으며 전체 배포 빌드는 미통과다.

검증 중 루트 `node_modules/firebase-admin`이 비어 있어 공통 관리자 API가 컴파일되지 않았다. 저장소에 이미 설치된 Functions의 동일 버전 13.10.0을 빈 패키지 디렉터리에 복구했다. package/lockfile 및 포트 3000은 변경하지 않았고 서버 전체 재설치도 하지 않았다.

## 실제 서비스 검증 한계

실제 유료 생성, 과금, 운영 배포·push는 실행하지 않았다. 브라우저 검사는 분리된 context와 합성 fixture를 사용하며 생성·기획 POST를 차단했다. 외부 CDN 스타일과 Firestore 연결의 환경 제한은 앱 오류와 구분해 검사 결과에 남겼다. GIF·작업 ZIP 성공이 플랫폼 제출 완료나 심사 통과를 의미하지 않도록 화면에 구분했다.
